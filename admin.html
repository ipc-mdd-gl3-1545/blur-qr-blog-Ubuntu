运行环境
后端架构全景 实时状态载入中…
请求流向 数据流向 / 管理旁路（虚线） 实时健康探测 异常
一句话读懂：用户和管理员都用 HTTPS 打开 VM1 网关；网关挡攻击、限流、验身份后，只经内网 8080 把请求交给 Kubernetes 集群；集群里的 Ingress 按域名找到博客容器，容器再读写 MySQL 和 Redis。
Docker 在哪：站点不是直接装在系统上，而是打包成镜像后由 containerd 2.2.2 在集群里启动容器（Docker 的同类运行时，可直接跑官方 Docker 镜像）。Pod 就是“跑着容器的盒子”：VM2 跑 Ingress / blog / redis，VM3 只跑 mysql。
为什么多一块⑤：备份、可观测、Web 控制台都是旁路——不参与用户请求，但出问题时全靠它们定位和兜底，所以单独画一条，避免主链路被塞满。
